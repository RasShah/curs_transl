# Архитектура TableScript

`compile_text` выполняет чистую трансляцию без записи файлов: нормализация строк → лексер → рекурсивный спуск → неизменяемый AST → раскрытие fill → граф → топологический порядок → типы → Python. CLI отдельно отвечает за UTF-8, параметры и атомарную публикацию результата.

| Модуль | Ответственность |
|---|---|
| `diagnostics.py` | Координаты, исходный текст, единый формат ошибок |
| `nodes.py` | Типы узлов AST и адреса ячеек |
| `lexer.py` | Токены, комментарии, числа, декодирование строк |
| `parser.py` | Приоритеты, команды, дерево и ограничения вложенности |
| `semantic.py` | Раскрытие fill, определения, граф, циклы, вывод типов |
| `codegen.py` | Явные Python-выражения по проверенному AST |
| `runtime.py` | Арифметические ошибки, CSV и защита файлов |
| `compiler.py` | Объединение этапов и результат Compilation |
| `cli.py` | Командная строка и атомарная запись `.py` |

## Копирование формулы

Для цели `(c,r)` смещение относительно верхней левой ячейки fill равно `(dx,dy)`. У относительной координаты новая величина равна старой плюс смещение; абсолютная координата остаётся прежней. Рекурсивный обход переносит все ссылки и оба конца диапазона, включая вложенные вызовы. Каждый экземпляр формулы сохраняет координаты шаблона для диагностики. Исходный AST содержит узел Fill, а таблица Analysis.definitions — обычные определения каждой ячейки.

## Граф и типы

Граф хранится как `имя формулы → {имя зависимости: позиция ссылки}`. Повторные ссылки дают одно ребро, но учитываются в лимите раскрытых обращений. Обход выражения собирает все ссылки, в том числе из обеих ветвей IF и всех ячеек диапазонов. После построения таблицы определений проверяются отсутствующие адреса.

Итеративный DFS использует состояния «не посещена», «активна», «готова». Ребро в активную вершину образует цикл, который восстанавливается по текущему пути. Вершина включается в порядок после обработки зависимостей. Поэтому при выводе типа очередной формулы типы всех её ссылок уже известны. Длинная цепь ячеек не расходует стек Python; рекурсивны только выражения глубиной не больше 64.

Построение и обход графа требуют O(V+E) времени и памяти после раскрытия синтаксиса; раскрытие диапазонов и fill само имеет стоимость, пропорциональную числу полученных обращений и узлов. Размер CSV зависит от площади экспортируемого прямоугольника, включая пустые поля. Статическая система различает number, string, boolean и служебный range. Правила операций и функций приведены в USER_GUIDE.md.

## Генерация и выполнение

Каждая проверенная формула превращается в явное выражение Python; арифметические операции — в вызовы защищённых функций, IF — в условное выражение Python. Ссылки читают словарь `_cells`. Строки кодируются через `repr`, числовые литералы берутся из уже разобранных значений. Исходные фрагменты не вставляются как исполняемый Python. В сгенерированном коде нет eval, exec и динамической компиляции.

Текст runtime.py встраивается в выходной файл, который не импортирует пакет транслятора. Функция `compute()` возвращает словарь результатов, `main()` вызывает её, затем экспортирует CSV и обрабатывает ошибки. Контекст `_cell` добавляет имя ячейки, а операции сохраняют исходную строку и позицию. Условное выражение вычисляет только выбранную ветвь, но отдельные определённые ячейки вычисляются все.

Файлы `.py` и `.csv` публикуются через временный файл и `os.replace` в одном каталоге. Ошибки до публикации сохраняют прежнюю версию. При аварийном завершении процесса ОС может оставить временный файл; транзакционность при отключении питания не гарантируется.

Посмотреть реальные структуры можно командой `python tools/inspect_program.py examples/basic.tbl`. Результат включает AST, зависимости, типы и порядок; диаграммы с редактируемыми исходниками находятся в `docs/diagrams/`.
